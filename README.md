# FastOCR

macOS 原生实时翻译助手：**选择应用 → 本地语音识别 → 离线 / 百度机器翻译 → 悬浮字幕**。也保留固定屏幕区域字幕翻译及 ⌘⇧O 框选取字。

## 使用

需要 macOS 14 或更新版本。打开 `dist/FastOCR.app`，菜单栏会出现字幕图标。首次打开默认显示实时翻译设置。

1. 按 **⌘⇧O**，首次使用时按照提示授予「屏幕录制」权限；返回应用后会重新检查。仅在授权后仍无法截图时尝试退出并重新打开。
2. 拖动框选文字，松开鼠标识别；**Esc** 取消。过小选区可重新拖动。
3. 看到「已复制」提示后，在目标应用按 **⌘V**。右下角默认预览最多 4 行识别文本，6 秒后自动关闭；可选中文字复制、点击「复制全文」或「展开全文」。拖动提示窗顶部或展开全文后，自动关闭会取消，可点击关闭按钮。
4. 菜单栏 →「查看上次结果」可查看、选中或复制文字。关闭「识别后自动复制」后，识别完成直接显示结果。

支持简体中文、繁体中文、英文和日文。支持多屏和 Retina，每次在一个显示器内框选，不支持跨屏拼接。热键冲突时会提示，可继续从菜单栏启动识别。

截图和结果仅保存在内存中，不写入历史文件。普通 OCR 和离线字幕翻译不上传图片或文字；主动选择百度机器翻译时，仅向百度发送识别文字。剪贴板由系统管理，退出应用不会清空已复制内容。空白识别或失败不会覆盖已有剪贴板及上次成功结果。系统屏幕录制权限由用户手动授予，无需辅助功能权限。

## 应用音频翻译（V0.3.0）

菜单栏 → **实时翻译…** → 来源选择「应用音频」→ 选择正在运行的应用 → 准备本地语音模型和离线翻译模型（或配置百度）→ **开始监听**。等待模型准备完毕、界面出现等待播放的提示后，在所选应用播放内容。

- 默认只监听所选应用，按进程和应用标识筛选；不会在应用不可用时退回全系统音频。应用退出后暂停，结束本次翻译并刷新列表可重新选择。浏览器按应用捕获，可能包含多个标签页；第一版不选择单个标签页或音频输出设备。
- 只采集播放声音，不启用麦克风。音频通过内存和本地进程管道传输，不保存录音；选择百度时只上传识别文字。首次下载模型需要联网，准备完成后可全程离线。
- 本地使用 [whisper.cpp v1.9.3](https://github.com/ggml-org/whisper.cpp/tree/v1.9.3) 和多语言 small-q5_1 模型，支持中、英、日语识别。简繁是文字输出形式，中文语音不区分简繁；目标语言可选简体、繁体、英语、日语。短片段建议手动指定来源语言。
- 语音按能量和停顿分段：约 0.5 秒静音收句，最长默认 3 秒，可调整到 2–6 秒。这是简单能量检测，音乐、人声混合和低音量可能影响效果，长句切分可能切断词语。音量条可帮助确认是否收到声音。
- 采集与识别分离：最多保留 2 段待识别音频，积压时丢弃最旧完整片段，并显示提示；超过时效的识别结果不再翻译。单次识别设有超时，错误后继续下一段。文字翻译沿用最新结果优先、超时跳过和旧结果隔离，不无限排队。
- 模型在开始采集前预加载，最长等待 45 秒；本机首次加载曾约 15 秒，热运行 3 秒英文片段约 0.2 秒。这只是样本推理耗时，实际字幕还需等待分段、翻译和显示，不是端到端延迟承诺。
- 暂停会停止采集；约 5 秒无声音时清空旧字幕。透明度、字号、对齐、拖动和穿透与屏幕字幕模式共用。

语音模型约 181 MiB，位于 `~/Library/Application Support/FastOCR/Speech`。界面可下载，也可执行 `bash Resources/Speech/setup.sh`。下载固定版本并校验 SHA-256；语音组件已随应用打包，运行它不依赖 Python。屏幕与系统音频访问使用系统授权，首次点击开始时引导，不需要麦克风权限。

**验证边界：** 已验证本地语音模型、进程通信、取消后恢复和分段缓冲；尚未在真实应用播放场景完成采集隔离及悬浮窗人工验收。部分受保护内容可能无法捕获，浏览器子进程、后台播放和多显示器需要现场验证。

## 屏幕字幕翻译

菜单栏 → **实时翻译…** → 来源选择「屏幕区域」→ 选择语言 → **框选字幕区域**。只框住一至两行原字幕；区域固定在当前显示器上，播放器移动或缩放后需重新框选。

- 源语言：自动、简体中文、繁体中文、英文、日文；目标默认简体中文，可切换其他三种语言。短句或纯汉字日文建议手动指定源语言。
- 悬浮窗展示原文与译文，可拖动背景移动、缩放窗口、暂停/继续、重新框选、结束。设置中可调整字号、背景透明度、文字透明度、水平靠左/居中/靠右、垂直靠上/居中/靠下和鼠标穿透；显示设置立即生效。位置相对于字幕窗口，默认居中；透明度 0% 为不透明、100% 为完全透明，控制按钮不会跟着文字消失。穿透后使用菜单栏控制。
- 连续采集固定区域，不捕获音频，排除 FastOCR 自身窗口。约每 250 毫秒进行一次 OCR（不含 OCR 耗时），只保留最新画面，短暂稳定后翻译。翻译调度不积压历史字幕：新稳定字幕取消旧请求；限流等待期间只保留最新一句；旧请求晚到不能覆盖新字幕。字幕消失约 0.7 秒后清空。
- 单句最长等待默认 3 秒，可设为 1–10 秒。超时/翻译失败跳过本句并继续监听，不再暂停整条识别流程；本句不会无限重试，后续字幕正常发起新请求。即使底层迟迟不返回，调度层也会释放当前请求。离线推理取消时会结束旧进程，必要时强制终止，下一句重新启动；频繁取消可能增加模型重载开销。截图/OCR 错误仍会暂停并提示。
- 字幕翻译不写剪贴板。普通 ⌘⇧O OCR 会暂停正在运行的字幕翻译；之后可从菜单栏继续。显示器变化后结束翻译并要求重新框选。

### 离线模型

兼容 macOS 14 的本地方案使用 CTranslate2 + Argos 语言包。首次准备模型需要联网；准备完成后，Python 翻译进程只通过本地管道通信，不启动 HTTP 服务，不调用在线翻译，不自动回退到云端。

设置中点击「准备离线模型」。需要先安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)，安装器会查找 PATH、`~/.local/bin`、`/opt/homebrew/bin` 和 `/usr/local/bin`。开发环境也可执行：

```sh
bash Resources/Offline/setup.sh
```

语言包及独立 Python 环境位于 `~/Library/Application Support/FastOCR/Offline`，当前本机安装约 458 MB，建议预留 1 GB 用于下载和解压。原始包的 README 和元数据一起保留；模型不提交到 Git，也不内嵌到应用。复制 `.app` 到另一台机器后需重新准备环境。高级部署可将已准备的环境与模型离线迁移，但 Python 环境路径与架构需要匹配。

语言路径：中英双向、日英双向；中日之间经英文中转；简繁通过系统文字转换完成。**这是轻量模型的初版，口语、人名可能误译，尤其翻成日文质量较弱。** 简繁转换也不保证台湾/香港/大陆地区术语本地化。超出 150 个模型 token 的输入会明确报错，避免静默截断。

本机短句样本的模型热运行耗时约 40–210 ms，首次加载样本约 1.4 秒；这不是端到端延迟承诺，不包括 OCR、稳定等待与画面呈现。

### 百度机器翻译 API

设置中主动切换「百度机器翻译」，填写百度翻译开放平台的 **APP ID** 和**密钥**，再点击「保存密钥」。使用[百度通用文本翻译 API](https://fanyi-api.baidu.com/doc/21)，固定通过 HTTPS POST 发送表单，按官方协议生成签名。不使用大模型聊天接口，也不需要模型名称或自定义接口地址。

密钥按 APP ID 保存在系统钥匙串，不写入偏好设置或日志；只发送当前识别文字，不发送录音或截图，不跟随重定向。简体/繁体/英语/日语分别映射到 `zh`/`cht`/`en`/`jp`。默认请求间隔 1.1 秒，可按账号实际调用限额调整；等待期间新字幕覆盖旧字幕，不排队补译已过期内容。限流、鉴权和余额错误有明确提示。

旧版大模型接口配置不会迁移为百度凭据；升级保留字号、背景透明度等设置，旧在线模式回到离线，需手动配置百度账户。百度签名、编码、多行响应及错误处理已用模拟响应验证；未提供真实凭据，尚未进行在线服务实测。

### 验证与已知边界

```sh
swift test
# 安装模型后，额外运行真实本地翻译和进程取消验证
FASTOCR_TEST_OFFLINE=1 FASTOCR_TEST_SPEECH=1 swift test
```

自动验证覆盖日文 OCR、简繁转换、字幕去重、短暂空白、逐字字幕最大等待、取消与恢复，以及旧请求挂起时新请求继续、晚到结果丢弃、限流期间只保留最新字幕、超时释放请求和百度接口模拟响应。另有旧设置迁移、透明背景与对齐设置保存验证。桌面自动化连接曾超时，真实视频上的框选/持续捕获/悬浮窗仍需人工验收，特别是全屏、多屏、鼠标穿透及录屏权限变化。受保护的播放器画面可能无法捕获；快速闪过的字幕可能漏识别。

## 构建与开发

安装 Xcode 或匹配的 Apple 开发工具，Swift 5.9+，以及 cmake 或 uv。构建脚本会下载校验固定版本 whisper.cpp，编译并签名本地语音组件；首次构建需要联网，模型另行准备：

```sh
./scripts/build.sh
open dist/FastOCR.app
```

构建脚本生成本机架构的 Release 应用，默认使用本地 ad-hoc 签名。建议将应用放在固定位置使用。更新本地签名构建后，macOS 可能要求重新授予录屏权限。

```sh
swift test
open Package.swift
```

`swift test` 包含真实 Vision 中英文图片识别、空白图片、Retina 翻转、外接屏比例和越界裁剪测试。通过 Xcode 打开 Package.swift 可调试源码；日常使用应启动打包后的 `.app`，以便系统正确识别权限归属。

## 结构

- `Sources/OCRCore`：可替换的 `OCREngine`、Vision 实现、带置信度和坐标的结构化结果、坐标换算。
- `Sources/FastOCR/Capture.swift`：ScreenCaptureKit 静态截图，每屏独立选区面板。
- `Sources/FastOCR/GlobalHotkey.swift`：Carbon 系统热键。
- `Sources/FastOCR/FastOCRApp.swift`：菜单栏、权限引导、流程状态、剪贴板、HUD、SwiftUI 结果窗口。
- `Resources/Info.plist`、`scripts/build.sh`：应用元数据与打包。

先冻结屏幕，再在截图上绘制蒙层；按截图实际像素尺寸裁剪，避免蒙层入图与 Retina 模糊。Vision 在后台执行，主线程保持响应。结果沿用 Vision 文本块顺序，复杂多栏、代码缩进和表格不保证原版式还原。

## 手动验收

- 首次启动、拒绝录屏权限、授权后重启均有清晰行为。
- ⌘⇧O 或菜单启动，拖选、反向拖选、Esc、极小选区均能恢复。
- 英文、中文、深色背景文字识别并复制；空白区域不覆盖剪贴板。
- 自动复制开关重启后保留，结果窗口支持复制全文。
- 分别在 Retina 内屏和普通外接屏框选，包含位于主屏左侧/上方的显示器。
- 全屏应用上框选、连续触发热键、选区期间断开显示器。

## 当前边界

当前版本未包含自定义快捷键、开机启动、持久化历史、PaddleOCR 或表格解析。当前产物用于本机运行；对外分发需要 Developer ID 签名和 Apple 公证，可通过 `CODE_SIGN_IDENTITY` 为构建脚本指定签名身份。

截图 API 参考：[Apple SCScreenshotManager](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager)。


## V0.1.2 响应与复制改进

- 快捷键不再固定等待 180 毫秒；各显示器并发截图，仍保持整组画面准备好后进入选区。
- 菜单栏即时显示准备/识别状态；截图排除应用自身窗口，避免菜单、结果提示进入截图。
- 屏幕配置变化会取消正在准备的选区；裁剪失败单独提示，不再当成用户取消。
- 自动复制开关按本次识别开始时的状态执行。自动与手动复制共用写入、即时回读校验；失败明确提示，结果仍可查看。
- 回读只能确认写入当时的结果，无法阻止其他软件之后改写剪贴板。写入失败也可能发生在清空之后；本版不会尝试恢复其他应用提供的旧剪贴板数据。

性能诊断采用 macOS 统一日志，子系统 `com.chenchao.FastOCR`、类别 `performance`，记录枚举耗时、各屏截图耗时、选区准备耗时、OCR 耗时和复制是否成功，不记录图片或识别正文。可在「控制台」启用信息消息并按子系统过滤，或执行：

```sh
log stream --level info --predicate 'subsystem == "com.chenchao.FastOCR" AND category == "performance"'
```

`selection_ready_ms` 是快捷键处理开始到准备展示选区的耗时，不包含显示器实际呈现延迟；真实速度仍取决于系统截图服务及显示器配置。剪贴板测试使用独立测试剪贴板，不改写用户剪贴板。


## V0.1.3 权限流程

| 功能 | 权限决策 |
| --- | --- |
| 屏幕截图 | 使用 CoreGraphics 检查/用户触发申请；实际捕获由 ScreenCaptureKit 验证 |
| Carbon 快捷键 | 不额外申请辅助功能或输入监控 |
| 本地 OCR、剪贴板、HUD | 不添加额外系统授权 |

权限服务统一负责检查、申请去重和申请后复查。未获得访问不等同于用户拒绝；系统接口不能区分未申请与拒绝。每个进程首次需要权限时允许系统申请，此后引导设置，避免反复请求。启动及重新激活仅检查状态，不发起申请或截图。菜单栏展示状态，并支持在 Finder 定位当前应用；设置打开失败提供手动路径。设置导航成功不表示已授权。

申请后立即检测已可用时继续用户本次框选；从设置返回只更新状态，需要再次触发识别。重启不是固定要求，保留手动退出/重开方式。截图失败会重新检查权限；已授权情况下显示实际捕获错误。

宿主无需为 CoreGraphics 屏幕授权配置强制 usage key，已移除不作为授权依据的 NSScreenCaptureUsageDescription。签名仍为本地 ad-hoc；没有改动系统权限，也没有添加 Sandbox 或其他权限。建议固定安装到同一路径，正式发布使用稳定签名身份。

新增权限状态测试使用注入检查/申请函数，覆盖刷新无副作用、授权撤销、已授权免申请、申请后复查、申请返回值与检测不一致、重入去重。人工验收仍需在真实 .app 上执行：首次允许/拒绝、设置返回、授权撤销、连续触发、刚授权后截图和必要时重启恢复；逻辑测试不代表 TCC 实机验收通过。
